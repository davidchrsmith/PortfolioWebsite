# Personal Portfolio

My personal portfolio website showcasing my **projects, professional experience, technical skills, and background**. The site features an interactive 3D hero section and a contact form powered by EmailJS.

The portfolio is built with modern React tooling and is deployed through GitHub Pages with an automated GitHub Actions workflow.

## Tech Stack

- **React 19** — UI development
- **Vite** — Build tool and development server
- **Three.js + React Three Fiber** — Interactive 3D hero section
- **Tailwind CSS v4** — Styling and responsive design
- **EmailJS** — Contact form functionality without a dedicated backend
- **GitHub Actions** — Automated deployment
- **GitHub Pages** — Hosting

## Features

- Interactive 3D hero section
- Responsive design for desktop and mobile
- Project and experience showcase
- Technical skills overview
- Contact form with EmailJS integration
- Automated deployment through GitHub Actions

## Local Development

Clone the repository and install the dependencies:

    npm install

Start the development server:

    npm run dev

The site will be available at:

    http://localhost:5173/PortfolioWebsite/

The `/PortfolioWebsite/` subpath is configured in `vite.config.js` to match the GitHub Pages deployment path.

## Deployment

The website is deployed automatically to GitHub Pages using GitHub Actions.

The deployment process is:

1. Changes are pushed to the `main` branch.
2. GitHub Actions installs dependencies and builds the project.
3. The production build is generated in `dist/`.
4. The compiled site is published to the `gh-pages` branch.
5. GitHub Pages serves the contents of the `gh-pages` branch.

The deployment workflow is defined in:

    .github/workflows/deploy.yml

The live website is available at:

https://davidchrsmith.github.io/PortfolioWebsite/

### Branch Structure

- **`main`** — Source code and project development
- **`gh-pages`** — Production build generated by the deployment workflow

The `gh-pages` branch is generated automatically and should not be edited manually.

## EmailJS Configuration

The contact form uses EmailJS, so no separate backend is required.

EmailJS credentials are provided to the application through Vite environment variables during the build process. Production credentials are stored securely as **GitHub Actions Secrets** and are not committed to the repository.

The required GitHub Actions secrets are:

    VITE_EMAILJS_SERVICE_ID
    VITE_EMAILJS_TEMPLATE_ID
    VITE_EMAILJS_PUBLIC_KEY

For local development, create a `.env.local` file in the project root:

    VITE_EMAILJS_SERVICE_ID=your_service_id
    VITE_EMAILJS_TEMPLATE_ID=your_template_id
    VITE_EMAILJS_PUBLIC_KEY=your_public_key

`.env.local` is gitignored and should never be committed to the repository.
